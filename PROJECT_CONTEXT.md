# PROJECT_CONTEXT.md — E4LA Website

Summary of the current site, based solely on the project files as they exist today.

## What E4LA is

E4LA ("Evolve for Los Angeles") is a strategy and creative consultancy in Los Angeles (est. 2017), offering experience strategy, creative direction, SEO/GEO, and AI/digital innovation services, plus a 1:1 advisory/coaching session product. Contact is via `info@e4la.org`.

- **`index.html`** — Home page: hero, services overview, approach/process, stats, "Why E4LA," coaching/advisory section with a booking calendar, closing CTA band, shared footer.
- **`services.html`** — Services detail page: hero, a pinned/scroll-driven panel sequence walking through 5 service categories, closing CTA banner, shared footer.
- **`about.html`** — About page: hero + principle cards, a 7-step company timeline, team profiles, AI capability/governance cards, final CTA band. First page to use the per-page CSS/JS split (`assets/css/about.css` + `assets/js/about.js`) instead of the global `style.css`/`script.js`.
  - **Timeline description reveal (`.milestone-reveal`)**: at ≥861px each milestone shows only its year + heading + a compact image thumbnail; the paragraph sits inside `.milestone-reveal`, a single-cell grid collapsed to `grid-template-rows:0fr`, and expands to `1fr` on `:hover`/`:focus`/`:focus-visible` of the `.milestone-card` (`tabindex="0"`), pushing that card's own image thumbnail down as the text grows in — not an overlay over the image. There is no build step — pages are static HTML that reference their CSS/JS directly (with cache-busting `?v=` query strings on the live pages).

**Card material on `about.html` / `our-work.html`.** Both pages share one frosted-glass recipe, defined as `--glass-fill` / `--glass-blur` / `--glass-depth` (plus `-hover` and `-inner` variants) in each file's `:root`. The cards used to be a dark fill; they are now a light translucent veil over a real `backdrop-filter` blur, so the page's colour reads through them. The "3D" depth comes from the inset layers in `--glass-depth`: a bright catch on the top edge, a hairline around the inner perimeter, then a wide soft shade drawn inward from every edge — that inner-wall shade is what reads as thickness. Nested panels inside a card (`.status`, `.growth-path li`) use `--glass-depth-inner`, which is shade-only, because stacking a second `backdrop-filter` inside the first turns both to mud. In `about.css` the winning `.card` rule is the **later** of the two blocks; edit that one. `.card` keeps `overflow:hidden` (needed so `.card::before`'s radial wash doesn't poke past the rounded corners). **The tokens are duplicated in both stylesheets — change both together.**
  - An outer coloured "self-glow" per card (an `rgba(var(--accent-rgb,...))` halo bleeding outside the card) was tried and explicitly rejected — reverted. Do not reintroduce it without being asked. If it comes back: it cannot be baked into `--glass-depth` itself (a custom property's `var()` references resolve once, at the element where that property is *declared* — `:root` has no `--accent-rgb`, so it would permanently bake to the fallback for every consumer); it would need to be a literal shadow layer appended directly in each consumer's own `box-shadow`, and `.card`'s `overflow:hidden` would need to go (it clips an element's own outer box-shadow), replaced with `border-radius:inherit` on `.card::before` so that pseudo-element still self-clips.

**Hero vertical position on `about.html` / `our-work.html`.** `.page>.section:first-child` uses `align-content:end`, not `center` — content sits toward the bottom of the one-viewport hero, leaving open space under the nav. This is safe on short/mobile viewports precisely because `min-height` is a floor, not a ceiling: once stacked content (hero-copy + hero-visual, or hero-copy + principles) exceeds one screen, the box just grows to fit and there is no "extra space" left for `align-content` to redistribute, so content still starts right under the nav rather than overflowing upward behind the sticky bar. The next section can never show inside the hero's own viewport for the same reason — it only starts once the (possibly taller-than-100vh) hero box ends. **Duplicated in both stylesheets — change together.**

## Design direction

- Dark base theme: background `#07060D`, white text, gold/purple "neon" accent system for CTAs (`.cta-neon`, with `--gold`/`--purple` variants and an animated SVG beam/shimmer border).
- Typography: Manrope (loaded via Google Fonts, weights 200–800), `system-ui`/Arial fallback.
- A palm-leaf motif recurs throughout: the logo, a small palm badge inside every CTA, and a decorative palm SVG symbol.
- Recurring visual pattern: an eyebrow label (`section-eyebrow`) + heading (`section-heading`, often with a `.grad-text` gradient-highlighted span) + supporting copy, repeated per section.
- `style.css` is structured as a long sequence of dated/iterative "PASS"/"FINAL ..." comment blocks that each override or refine earlier rules (not a clean single-pass stylesheet) — later blocks in the file generally win. New styling should be added as new, clearly scoped blocks rather than edits scattered through old passes.

Nav styling lives exclusively in `assets/css/nav.css` — do not re-add nav rules to any page stylesheet (see that file's header comment for why).

## Responsive behavior

- No CSS framework/grid system — layout is hand-written with a wide range of ad hoc breakpoints across the stylesheet's history: common ones are `1280px, 1200px, 1180px, 1120px, 1100px, 1024px, 980px, 960px, 900px/899px, 780px, 768px, 700px/701px, 640px, 560px, 430px`.
- Several interactive features are explicitly **desktop-only** and fall back to a simpler static/stacked layout below a breakpoint (see below): the 3D service-card tilt, and the pinned scroll-step section on `services.html`.
- `prefers-reduced-motion: reduce` is respected throughout — auto-cycling timelines, the CTA beam shimmer, and the tilt effect all short-circuit to a static state when set.

## Pinned-scroll sections

- **`services.html` — `.svcd-pin`**: a 500vh-tall wrapper holding 5 service-category panels (`.svcd-pin__panel`). `script.js` manually toggles the stage between `position: fixed` / `absolute` / normal flow based on scroll position (deliberately *not* using CSS `position: sticky`, because the site's global `body { overflow-x: hidden }` breaks sticky positioning for descendants in Chrome/Safari). Panel transform/opacity and each panel's decorative "blob" (scale/rotation/blur) are driven continuously by scroll progress. A row of dots (`.svcd-pin__dot`) tracks the active panel.
  - Gated to `min-width: 640px` **and** `pointer: fine` — below that, or on coarse/touch pointers, it tears down to a plain stacked list (no scroll-jacking).
  - Layout-critical positioning is asserted via inline `!important` styles from JS as a deliberate safeguard against stale/cached CSS not applying — visual styling (colors, fonts) still comes from `style.css`.

## Other interactions and animations (`script.js`)

- **Scroll reveal**: any element with `[data-r]` (optionally staggered via `data-d="n"`) fades/slides in once via `IntersectionObserver`, adding an `.in` class.
- **Hero word scramble**: `#js-word` cycles through a word list (`experiences, brands, stories, presence, impact, culture`) with a scramble/decode text effect every 2s.
- **Service cards (`.svc-card`)**: idle cards auto-drift with a per-card "personality" (distinct sine-wave frequency/phase/amplitude combo) via CSS custom properties (`--svc-rx/--svc-ry/--svc-scale`); hovering/focusing freezes a card flat instead of tracking the pointer. Gated to `hover:hover`, `pointer:fine`, `min-width:900px`, and disabled under `prefers-reduced-motion`. Each card's icon is actually a muted looping `<video>` frozen at frame 0 at rest, playing only while hovered/focused (independent of the tilt gating, so it also works on touch).
- **CTA neon beam + badge sizing (`.cta-neon`)**: for every CTA button, JS measures the button's true rendered height (temporarily zeroing the badge box to avoid a feedback loop) to size the circular palm badge, and builds/sizes a repeating SVG gradient traced around the button's border (3 evenly-spaced bright "peaks", animated via SMIL `animateTransform`) for the shimmer effect. Recomputed on load and on resize (via `ResizeObserver` where available).
- **Approach timeline (`#approach .tstep`)** and **coaching "how it works" timeline (`#coaching .coaching__timeline li`)**: both auto-cycle through their steps on a timer (1100ms and 2000ms respectively), pausing when the tab is hidden and respecting reduced motion (lights step 1 and stops).
- **Audience selector cards** (`.aud-card`, coaching section): click/keyboard-selectable single-choice cards, styled via inline style toggling (not classes).
- **Calendar widget** (coaching section): plain date-cell selection (adds/removes `.cal__date--today`); "Book Session" button opens a `mailto:` link.
- **Newsletter form** (`#js-nl`, footer): client-side only — shows a checkmark on submit, no real submission/backend.
- **Smooth scroll delegation**: any `[data-scroll-to="#selector"]` element smooth-scrolls to that target on click.

## `our-work.html` specifics

- **Hero overview rail (`.hero-rail`)**: a vanilla reimplementation of the interactive image-accordion pattern (reference: the 21st.dev `interactive-image-accordion` React/Tailwind component — reimplemented, not installed). Five panels, one expanded; siblings collapse to a rotated vertical label. Built on `flex-grow` ratios (collapsed `1`, active `5.4`) so the rail always fills its container at any width, and the rail height never changes, so expanding cannot shift the page. Each panel is a real `<a>` to a section anchor, making the hero double as the jump navigation for a long page. Hover activates on fine-pointer devices, `focus` activates everywhere, arrow keys/Home/End move focus. A gentle 3.4s auto-advance runs until the first interaction, then stops for good. Below 900px it keeps the same accordion behaviour but **turns its axis**: one panel open, four full-width 58px bars collapsed, tap to switch. It is not a plain list. A horizontal rail cannot work at that width — at 375px the four closed columns come out ~36px wide, under the 44px touch minimum, and narrowing the open panel to buy them width leaves it unable to show anything. Total rail height is constant (four bars + one open) so switching never shifts the page. On hover-less devices the first tap opens a panel and a second follows the link, otherwise the page would jump to a section the reader never saw; the auto-advance is off there, since a vertical switch mid-scroll moves what is under the reader's thumb.
  - **All panels share one surface in both states**: a dark translucent wash that lets the page's own blue→purple→pink gradient read through, so the rail sits *in* the background rather than on top of it as a lighter card. Identical across all five panels, and deliberately still visible when a panel opens, where it frames the artwork. The accent colour appears only on the open panel's border and glow. Closed panels show no artwork at all — five images side by side left the closed rail with no focal point.
  - **The two states are styled from opposite ends and that split is deliberate.** *Closed*: one dark surface identical on all five panels, no accent tint, no artwork, and the label alone — large (20px), bold, rotated, and carrying the site's own `#DB2777`→`#F97316` gradient via `background-clip:text` (the same one `.gradient-text` puts on the h1 beside it). *Open*: the accent-tinted panel with full-bleed artwork and the small solid-white label above the description, exactly the original treatment. Several intermediate versions (uniform white veil, arithmetic label placement, square image frame) were tried and reverted — do not reintroduce them without being asked.
  - Closed labels are centred by giving `.hero-rail__body` `inset:0` + `align-content:center` and taking `.hero-rail__meta`/`.hero-rail__cue` **out of flow** while closed. Those two are the whole reason the closed labels once sat at five different heights: in flow, their variable copy height pushed each label to a different offset. The open state puts them back in flow under a bottom-anchored body. Note the pink gradient stop measures ~4.1:1 on the panel surface, just under AA for text — a property of the brand palette (the eyebrow colour has the same issue site-wide), accepted for brand consistency rather than substituted.
  - Panel artwork lives in `assets/our-work/hero/*.webp` (5 files, ~300KB total, resized to 800² from ~2.2MB of source JPGs). Each is the mascot on a solid black field, composited with `mix-blend-mode:screen` so the black drops out with no alpha keying and the panel's accent gradient still reads through; the panel needs `isolation:isolate` to contain that blend. `--focal` is set per panel inline and carries **both** axes, because the panel is portrait in the two-column hero and landscape once the hero stacks — only the overflowing axis is used, and a plain centre crop cut the mascot's head off below ~1100px.
- **Paint Events photo frames** (`.paint__tiles` / `.paint__tile`): eight frames start stacked behind the Paint Events mark and fan out onto a ring as the section scrolls in. `our-work.js` writes a single 0→1 number to `--paint-open` on `.paint__visual`; all the geometry is in `our-work.css`. The progress is measured with a rect read in a rAF-throttled passive scroll listener, **not** Motion's `scroll()` — that constructed without error but never delivered a callback on this page. It lives in the page's plain script rather than `motion.js` because of the `file://` constraint below. Each frame rotates to its angle, translates outward, then counter-rotates so the photo stays upright — the rotation only aims the translation. Two things to preserve: `--paint-r`/`--paint-tile` are **lengths, not percentages** (a percentage in `translateY` resolves against the frame's own height, not the circle), so they are re-set per breakpoint next to the circle's `max-width` and must clear the logo disc (64% of the circle) without crossing the outer ring; and the stylesheet's default for `--paint-open` is **1, not 0**, so the section still looks finished if the module never loads — do not pre-set it to 0 in JS. The frames are empty placeholders; dropping an `<img>` into one fills it and removes the hatch automatically (`.paint__tile:empty`).
- **Organization wall**: all 34 organizations are authored directly in the HTML, not fetched. The earlier standalone version loaded them from `our-work-data.json` via `fetch()`, which left the section empty under `file://` and kept every organization name out of the HTML source (bad for SEO and AI answer engines). Filtering now only toggles `[hidden]` on cards, matched against each card's pipe-delimited `data-groups` attribute.
  - **Card order is deliberate and hand-set, not alphabetical or by category.** The first 24 cards are the team-building / Paint Events engagements in a specific requested order (USC, LMU, Team Prime Time, After-School Programs, PwC, HumanGood, SoLa Impact, Snowball Agency, PCACIPA, ADM Events, Electica, Conrad N. Hilton Foundation, Golden Hippo, ClubLed, The PR Guild, Majestic Lighting, Hollywood Post 43, DaVita Kidney Care, Glendale Health Community Center, Castle Argyle Arms, Edmund Honor Bourbon, Roosterfish, Pars Equality Center, NIPOC); the remaining 10 follow. Filtering preserves DOM order, so this sequence drives every filtered view too. Keep new cards in the intended position rather than appending.
  - The Paint Events section used to repeat those same 24 names as a chip list under "Creative experiences across teams and communities." That list is removed — the wall above now leads with them, so the block is a heading plus a closing statement that links up to `#organizations`. Do not reintroduce a per-organization list there.
- **The logos scroll as four marquee rows**, alternating direction, built by `our-work.js` from the grid markup. Four short rows (~9 each) rather than one or two long ones is deliberate: a short row loops quickly so every logo comes back around often, and the block collapses from seven static grid rows to four. `.organization-grid` stays in the document as the no-JS **and** `prefers-reduced-motion` form — the script moves the real cards into rows and only then hides the grid, so nothing depends on JS being present. Real cards are *moved*, never copied; only the filler copies that make each loop seamless are clones, and those are `aria-hidden` with `tabindex="-1"`. Row length and speed are computed **after** the logo images decode (`whenImagesReady`) — measuring first gave the four rows visibly different tempos and left one loop a few px short. Speed is a constant ~55px/sec so all rows run at one tempo. Rows pause on hover and on `focus-within`, which both makes the links hittable and satisfies the pause requirement for auto-moving content. Filters rebuild the rows and the row count adapts (5 logos → 2 rows, 4 → 1). The per-logo category/relationship lines have no room on a scrolling row, so they are clipped rather than `display:none` — several cards are plain divs with no link and no aria-label, and that text is their only description.
- **Monochrome logo treatment**: no cards, no tiles, no per-logo backgrounds. Every mark is flattened with `filter: brightness(0) invert(1)` to a white silhouette and dissolved into the page background at `opacity: .55` (full opacity on hover/focus). This is the only treatment that normalises the sources, because their ink polarity is mixed — some marks are dark artwork on transparency (USC, PwC, Hilton), others light (Team Prime Time, HumanGood) — so no tint, grayscale or blend mode lands consistently on all of them. Brand colour is deliberately given up; this was an explicit decision, and the full-colour originals are kept in place.
  - Three sources had opaque backgrounds and would have flattened into solid white blocks — `electica-logo.png` and `paint-events-logo.png` (white) and `pars-equality-center-mark.png` (`#013772`). They use alpha-keyed `*-alpha.png` variants generated with `ffmpeg -vf colorkey=<bg>:<similarity>:<blend>`. Originals sit next to them; if a new logo with an opaque background is added, it needs the same treatment or it will render as a block.
  - Optical sizing uses a `--logo-scale` **multiplier** on the card and a `--logo-base` length on the brand box, never absolute image heights. Per-organization selectors outrank a plain `.organization-card__brand img` rule, so absolute heights would survive the mobile breakpoint and overflow the shorter row. Breakpoints move `--logo-base` only.
  - The same treatment is applied to the two other logo spots on the page (`.radio-brand` in the KIRN impact card, `.paint__logo-wrap` in the Team Building section), so there is exactly one logo style on the page.

## Known constraints worth remembering

- **The site is regularly opened straight from disk over `file://`, not just through a server.** Two things silently break there, and both have already caused bugs on this page:
  - **`<script type="module">` never executes.** Modules are fetched with CORS and a `file://` origin is `null`, so the browser blocks them. `motion.js` is a module, so *anything that has to work from disk cannot live in it* — that is why the Paint Events scroll animation sits in `assets/js/our-work.js` instead. The failure is silent in the sense that the page still renders; only the scripted behaviour is missing.
  - **`fetch()` / `XHR` are blocked**, which is why the 34 organizations are authored directly in `our-work.html` rather than loaded from `our-work-data.json`.
  - Plain `<script src="...">` (including with a `?v=` query) works fine over `file://`. Prefer it for anything behavioural on this page.

- `body { overflow-x: hidden }` is global and is the reason the services pinned-scroll section can't use `position: sticky` — see above.
- Live pages use `?v=` cache-busting query strings on `style.css`/`script.js`/asset URLs; bump these when shipping a change that must not be served stale.
- `style.css` history is additive/override-heavy (many `!important` rules from successive "FINAL ..." passes) rather than a clean single source of truth per property — check for later overriding blocks before assuming an early rule is the one in effect.
